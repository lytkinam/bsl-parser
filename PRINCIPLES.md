# Принципы разработки (SDQL / bsl-parser)

## 1. Формат первичен

**Выходной JSON-формат определяется пользователем и является главным.**

- Если пользователь дал пример структуры — реализовать его **строго**, без самовольных добавлений.
- Не добавлять поля, которые не были запрошены (например, поле `type` в `HierarchyNode`, которого не было в примере).
- Не менять названия полей (`type_hierarchy`, `table_hierarchy` — использовать точно так, как указано).
- Если формат неясен — **уточнить у пользователя**, а не додумывать.

## 2. Пример первее кода

**После разработки кода в обязательном порядке создавать пример на основе `middle_example.sql`.**

- Пример генерируется до коммита кода.
- За основу можно брать уже готовые промежуточные шаги из других папок.
- Пример коммитится в гит **отдельно** от кода.
- Только после подтверждения пользователем, что пример корректен — коммитить код.
- Не коммитить код в гит до проверки примера.

## 3. Одноуровневая структура по умолчанию

**Если пользователь показывает плоский список — делать плоский список, а не дерево.**

- `table_hierarchy` — это одноуровневый (плоский) массив прямых зависимостей узла.
- Каждый элемент содержит `id`, `name`, `type_hierarchy` — без вложенных `table_hierarchy` внутри элемента.
- Вся иерархия выражается через корневой массив узлов, а не через вложенность.

## 4. Минимальные изменения

**Изменять только то, что просят.**

- Не добавлять "на всякий случай" дополнительные поля, классы или логику.
- Не рефакторить смежный код без запроса.
- Если требуется новая функциональность — реализовать ровно её, не обобщая "на будущее".

## 5. Уточнять неясности

**При неоднозначности требований — задавать уточняющие вопросы.**

- Не строить догадки о том, что имел в виду пользователь.
- Лучше потратить один лишний раунд на уточнение, чем переделывать.
- Особенно критично для формата выходных данных и правил сопоставления (например, `id` виртуальных таблиц).

## 6. Тестирование на `middle_example.sql`

**Все тесты проходят на `middle_example.sql`.**

- `middle_example.sql` — эталонный тестовый набор.
- После любого изменения перегенерировать артефакты для `middle_example` и проверить их корректность.
- Пример должен содержать полный набор артефактов: SDBL_PARS, LINE_PARS, иерархия.
