# SRS 06.01: Доработка Java-модулей SDQL для MCP-интеграции

## 1. Назначение

Документ описывает доработку существующих Java-модулей проекта bsl-parser/SDQL для обеспечения возможности использования MCP-сервера. Java-модули не реализуют сам MCP-протокол — они предоставляют внутренний контракт (API), через который MCP-сервер (внешний по отношению к Java-коду) может управлять конвейером обработки SQL.

**Принцип:** MCP-сервер — это тонкая обёртка (adapter), которая транслирует MCP-запросы во внутренние вызовы Java-API. Java-код не зависит от MCP.

## 2. Текущая архитектура (проблемы)

Сейчас конвейер жёстко связан с файловой системой:

```
SdqlCli.main() → File input → File outputDir → String baseName
                ↓
    analyzer.analyze(input, outputDir, baseName)  // пишет в файлы
    lineParsBuilder.build(outputDir.toPath(), baseName)  // читает/пишет файлы
    ...
```

**Проблемы:**
1. Все Builder-ы работают только с `Path` (файловая система)
2. Нет возможности передать SQL-текст из памяти
3. Нет возможности получить результат в память (только файлы)
4. Нет единой точки входа для запуска конвейера из кода
5. `FullFieldLineageBuilder` уже имеет перегрузку с `List<TargetField>`, но она не используется в CLI

## 3. Целевой контракт (внутренний API)

### 3.1 Интерфейс `SdqlPipeline`

```java
package com.github._1c_syntax.bsl.parser.sdql.api;

/**
 * Единая точка входа для запуска конвейера SDQL.
 * Не зависит от MCP — может использоваться из любого контекста.
 */
public interface SdqlPipeline {

    /**
     * Запустить полный конвейер для SQL-текста.
     * Результат сохраняется в указанную директорию.
     *
     * @param sqlText     Текст SQL-пакета
     * @param outputDir   Директория для артефактов
     * @param baseName    Базовое имя (если null — генерируется автоматически)
     * @param detailed    Генерировать markdown-отчёты
     * @return PipelineResult с мета-информацией
     */
    PipelineResult analyze(String sqlText, Path outputDir, String baseName, boolean detailed);

    /**
     * Запустить полный конвейер для SQL-текста.
     * Возвращает результат в память (без записи в файлы).
     *
     * @param sqlText   Текст SQL-пакета
     * @param baseName  Базовое имя (если null — генерируется автоматически)
     * @return PipelineResult с моделями в памяти
     */
    PipelineResult analyzeInMemory(String sqlText, String baseName);
}
```

### 3.3 Интерфейс `ModelRepository`

```java
package com.github._1c_syntax.bsl.parser.sdql.api;

/**
 * Абстракция хранилища моделей.
 * Реализация для файловой системы — FileSystemModelRepository.
 * Возможна реализация для in-memory (тесты) или БД.
 */
public interface ModelRepository {

    void saveSdblModel(String baseName, QueryModel model);
    QueryModel loadSdblModel(String baseName);

    void saveLineParsModel(String baseName, LineParsModel model);
    LineParsModel loadLineParsModel(String baseName);

    void saveFullParsModel(String baseName, FullParsModel model);
    FullParsModel loadFullParsModel(String baseName);

    void saveHierarchy(String baseName, List<HierarchyNode> hierarchy);
    List<HierarchyNode> loadHierarchy(String baseName);

    void saveFieldLineage(String baseName, int nodeId, String alias, List<FieldLineageNode> lineage);
    List<FieldLineageNode> loadFieldLineage(String baseName, int nodeId, String alias);

    void saveFullFieldLineage(String baseName, int nodeId, String nodeName,
                               List<String> aliases, List<FullParsNode> fflNodes);
    List<FullParsNode> loadFullFieldLineage(String baseName, int nodeId, List<String> aliases);

    void saveRestoredQuery(String baseName, int nodeId, String alias, String sql);
    String loadRestoredQuery(String baseName, int nodeId, String alias);

    void saveVerificationReport(String baseName, VerificationReport report);
    VerificationReport loadVerificationReport(String baseName);

    boolean exists(String baseName);
    void delete(String baseName);
    List<String> listBaseNames();
}
```

### 3.4 Интерфейс `NodeResolver`

```java
package com.github._1c_syntax.bsl.parser.sdql.api;

/**
 * Разрешение идентификаторов узлов.
 */
public interface NodeResolver {

    /**
     * Найти узел по ID или имени.
     *
     * @param model     Модель FULL_PARS
     * @param nodeId    ID узла (приоритет)
     * @param nodeName  Имя узла
     * @return FullParsNode
     * @throws NodeNotFoundException если узел не найден
     */
    FullParsNode resolve(FullParsModel model, Integer nodeId, String nodeName);

    /**
     * Найти поле по alias в узле.
     *
     * @param node   Узел
     * @param alias  Alias поля
     * @return FullParsSelectField
     * @throws AliasNotFoundException если поле не найдено
     */
    FullParsSelectField resolveField(FullParsNode node, String alias);
}
```

### 3.5 Интерфейс `QueryRestorer`

```java
package com.github._1c_syntax.bsl.parser.sdql.api;

/**
 * Восстановление SQL из FFL.
 */
public interface QueryRestorer {

    /**
     * Восстановить SQL из списка FFL-узлов.
     *
     * @param fflNodes     Список узлов FFL
     * @param fullParsById Полная модель (для inline subqueries)
     * @return SQL-текст
     */
    String restore(List<FullParsNode> fflNodes, Map<Integer, FullParsNode> fullParsById);

    /**
     * Восстановить SQL из списка FFL-узлов (только FFL, без полной модели).
     *
     * @param fflNodes Список узлов FFL
     * @return SQL-текст
     */
    String restore(List<FullParsNode> fflNodes);
}
```

### 4.2 Рефакторинг `SdqlCli`

**Текущий код:**
```java
public class SdqlCli {
    public static void main(String[] args) throws Exception {
        // 8 шагов конвейера напрямую
    }
}
```

**Требуемый код:**
```java
public class SdqlCli {
    public static void main(String[] args) throws Exception {
        // Использовать SdqlPipeline вместо прямых вызовов
        SdqlPipeline pipeline = new SdqlPipelineImpl(
            new FileSystemModelRepository(outputDir.toPath())
        );
        PipelineResult result = pipeline.analyze(sqlText, outputDir.toPath(), baseName, detailed);
    }
}
```

**Изменения:**
- `SdqlCli` делегирует работу `SdqlPipelineImpl`
- Логика конвейера не дублируется

## 5. Правила изменения существующего кода

### 5.1 Обратная совместимость

- Все существующие public методы **сохраняются без изменений сигнатуры**
- Новые методы добавляются как перегрузки или новые классы
- Существующие тесты **не должны сломаться**

### 5.2 Минимальные изменения

- Не менять логику парсинга, моделей, именования
- Не менять формат JSON-артефактов
- Не добавлять зависимостей от MCP или HTTP

### 5.3 Что НЕ изменяется

| Компонент | Статус |
|-----------|--------|
| `model/` (QueryAst, DataSource, и т.д.) | Без изменений |
| `visitor/QueryPackageVisitor` | Без изменений |
| `NodeSplitter` | Без изменений |
| ANTLR4-грамматика | Без изменений |
| JSON-формат артефактов | Без изменений |

## 8. Пример использования API

```java
// In-memory анализ
SdqlPipeline pipeline = new SdqlPipelineImpl(new InMemoryModelRepository());
PipelineResult result = pipeline.analyzeInMemory(sqlText, null);

FullParsModel fullPars = result.getFullParsModel();
FullParsNode node = new NodeResolverImpl().resolve(fullPars, null, "ВТ_Суммы_ПР_ТранзитныеВиды");

// Построение FFL для нескольких полей
FullFieldLineageBuilder fflBuilder = new FullFieldLineageBuilder();
List<FullParsNode> ffl = fflBuilder.build(fullPars, node.getId(), List.of("Взносы", "ПенсионныйСчет"));

// Восстановление SQL
String sql = new QueryRestorerImpl().restore(ffl, fullPars.getNodes().stream()
    .collect(Collectors.toMap(FullParsNode::getId, n -> n)));
```
