# BRD02: Восстановление урезанного запроса для выполнения в 1С

## 1. Цель

На основании урезанной структуры `full_field_lineage` (FFL) восстановить работающий пакет SQL-запросов 1С (SDBL), который можно выполнить в консоли запросов или в коде 1С:Предприятие.

## 2. Входные данные

- `FFL_<baseName>_<nodeId>_<nodeName>_<alias>.json` — урезанная структура full_pars (плоский массив узлов)
- `FULL_PARS_model_<basename>.json` — полная модель full_pars (для получения недостающих метаданных: `from`, `into`, `order_by`, `unions`)

## 3. Выходные данные

- `RESTORED_QUERIES/<baseName>/<nodeId>_<nodeName>/<alias>.sql` — текстовый файл с пакетом запросов SDBL, разделённых `;`

## 4. Основные требования

### 4.1 Порядок запросов
Запросы в пакете должны идти в порядке топологической сортировки: сначала создаются ВТ-зависимости (листья графа), затем промежуточные узлы, в конце — target-нода.

### 4.2 Структура восстановленного запроса
Для каждого узла FFL строится запрос:
- **SELECT** — из `select[].text` с сохранением `alias`
- **INTO** — из `FULL_PARS_model` (`into`) для `temp_query`
- **FROM** — из `FULL_PARS_model` (`from[]`)
- **JOIN** — из `join_conditions[]` (тип соединения, источник, условие)
- **WHERE** — из `where_fields[].text`, соединённых через `И`
- **GROUP BY** — из `group_by_fields[].text`
- **HAVING** — из `having_fields[].text`

### 4.3 Обработка UNION
Узел с `union_nodes_ids` (виртуальный родитель) восстанавливается как конструкция `ОБЪЕДИНИТЬ ВСЕ` / `ОБЪЕДИНИТЬ` между всеми частями. Части берутся из `FULL_PARS_model`.

### 4.4 Обработка подзапросов
Подзапросы (`from[].subquery` как String) заменяются на имена соответствующих ВТ. Порядок создания ВТ обеспечивает, что к моменту использования подзапроса он уже создан.

### 4.5 Физические таблицы
Узлы, представляющие физические таблицы (leaf, `node_id=null` в `child_fields`), не создаются как отдельные запросы. Они используются в `FROM` / `JOIN` родительских запросов.

### 4.6 Условия
- Если `where_fields` пуст — блок WHERE отсутствует
- Если `group_by_fields` пуст — блок GROUP BY отсутствует
- Если `having_fields` пуст — блок HAVING отсутствует
- `join_conditions` восстанавливаются только если присутствуют

## 5. Пример

**Вход:** `FFL_middle_example_74_ВТ_Суммы_ПР_ТранзитныеВиды_ЗадолженностьПенсии.json`

**Выход:** `RESTORED_QUERIES/middle_example/74_ВТ_Суммы_ПР_ТранзитныеВиды/ЗадолженностьПенсии.sql`

```sql
// ... пакет запросов для воспроизведения поля ЗадолженностьПенсии ...
```

## 6. Ограничения

- Восстановленный запрос содержит только поля, присутствующие в FFL. Поля, не влияющие на результат target-поля, отсутствуют.
- Виртуальные таблицы регистров (`РегистрНакопления.XXX.Остатки`) восстанавливаются как есть.
- Параметры запроса (`&Дата`, `&Организация`) сохраняются из оригинального текста.
