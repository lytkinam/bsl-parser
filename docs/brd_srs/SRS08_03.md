# SRS 08.03: Docker-интеграция и автозапуск MCP-сервера MCP_QUERY_1C

## 1. Назначение

Документ описывает интеграцию MCP-сервера MCP_QUERY_1C (реализованного в SRS08) в Docker-инфраструктуру AI-стека, настройку автозапуска через systemd и обновление скилла `ubuntu-admin`.

**Принцип:** MCP-сервер MCP_QUERY_1C работает как Docker-контейнер внутри существующей сети `ai-network`, получает запросы по HTTP JSON-RPC 2.0 и использует fat-jar (shadowJar) для автономной работы.

## 2. Текущее состояние

- **MCP-сервер MCP_QUERY_1C**: реализован в `com.github._1c_syntax.bsl.parser.sdql.mcp_query_1c.McpQuery1cServer`
- **Порт по умолчанию в коде**: 8081 (в `McpQuery1cServer.java`)
- **Утверждённый порт для Docker**: 15372
- **Jar**: обычный jar (~577KB), не содержит зависимости
- **AI-стек**: работает (Redmine 3000, OpenViking 1933, LiteLLM 4000, Qdrant 6333, MCP Qdrant 8000, SDQL MCP 5372, MCP_QUERY_1C 15372)
- **Сеть**: `ai-network` (bridge, external) существует
- **systemd ai-stack.service**: не создан (или создан в SRS06_03 — требуется дополнение)
- **Скилл ubuntu-admin**: `~/.config/agents/skills/ubuntu-admin/` — нет раздела MCP_QUERY_1C

## 3. Целевое состояние

### 3.1 Shadow JAR

Плагин `com.github.johnrengelman.shadow` версии `8.1.1` уже добавлен в `build.gradle.kts` в рамках SRS06_03. Добавить отдельный `tasks.shadowJar` для MCP_QUERY_1C:

```kotlin
tasks.register<com.github.jengelman.gradle.plugins.shadow.tasks.ShadowJar>("shadowJarMcpQuery1c") {
    group = "build"
    archiveClassifier.set("mcp-query-1c")
    mergeServiceFiles()
    manifest {
        attributes["Main-Class"] = "com.github._1c_syntax.bsl.parser.sdql.mcp_query_1c.McpQuery1cServer"
    }
    from(sourceSets["main"].output)
    configurations = listOf(project.configurations["runtimeClasspath"])
}
```

Альтернативно: использовать единый shadowJar с двумя Main-Class не получится; рекомендуется собирать универсальный fat-jar и указывать нужный Main-Class при запуске:

```bash
java -cp app.jar com.github._1c_syntax.bsl.parser.sdql.mcp_query_1c.McpQuery1cServer ...
```

### 3.2 Dockerfile для MCP_QUERY_1C

Создать `Dockerfile.mcp_query_1c` в корне проекта:

```dockerfile
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY build/libs/*-all.jar app.jar
EXPOSE 15372
ENTRYPOINT ["java", "-cp", "app.jar", "com.github._1c_syntax.bsl.parser.sdql.mcp_query_1c.McpQuery1cServer"]
CMD ["--port=15372", "--storage-dir=/app/storage", "--external-mcp-url=http://192.168.117.247/npf_ops_users_test_popov/hs/mcp"]
```

### 3.3 Docker Compose

Создать `~/mcp-query-1c/docker-compose.yml`:

```yaml
services:
  mcp-query-1c:
    build:
      context: /tmp/bsl-parser
      dockerfile: Dockerfile.mcp_query_1c
    container_name: mcp-query-1c
    ports:
      - "15372:15372"
    volumes:
      - ./storage:/app/storage
    networks:
      - ai-network
    restart: unless-stopped

networks:
  ai-network:
    external: true
```

### 3.4 Скрипт запуска AI-стека

Обновить `~/.config/agents/skills/ubuntu-admin/scripts/ai-start-all-services.sh`:

```bash
#!/bin/bash
# Запуск AI-стека в правильном порядке

set -e

STACK_HOME="${STACK_HOME:-$HOME/ai-stack}"

start_compose() {
    local dir="$1"
    local name="$2"
    if [ -f "$dir/docker-compose.yml" ]; then
        echo "Starting $name..."
        docker compose -f "$dir/docker-compose.yml" up -d
    else
        echo "WARNING: $dir/docker-compose.yml not found"
    fi
}

# 1. Ollama (systemd)
sudo systemctl start ollama || true

# 2. LiteLLM
start_compose "$STACK_HOME/litellm" "LiteLLM Proxy"

# 3. OpenViking
start_compose "$STACK_HOME/openviking" "OpenViking"

# 4. Redmine + Qdrant
start_compose "$STACK_HOME/redmine" "Redmine"

# 5. SDQL MCP
start_compose "$HOME/sdql-mcp" "SDQL MCP"

# 6. MCP_QUERY_1C
start_compose "$HOME/mcp-query-1c" "MCP_QUERY_1C"

echo "AI stack started."
```

### 3.6 Systemd unit

Обновить `/etc/systemd/system/ai-stack.service`:

```ini
[Unit]
Description=AI Stack Auto-Start (Ollama, Docker, LiteLLM, OpenViking, Redmine, SDQL MCP, MCP_QUERY_1C)
After=docker.service ollama.service network.target
Wants=docker.service ollama.service

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/home/user/.config/agents/skills/ubuntu-admin/scripts/ai-start-all-services.sh --auto
StandardOutput=append:/var/log/ai-stack.log
StandardError=append:/var/log/ai-stack.log

[Install]
WantedBy=multi-user.target
```

## 5. Проверка после выполнения

1. `./gradlew shadowJar` → создаёт `bsl-parser-0.1.0-SNAPSHOT-all.jar`
2. `docker compose -f ~/mcp-query-1c/docker-compose.yml up -d` → контейнер `mcp-query-1c` running
3. `curl -s http://localhost:15372/health` → `{"status":"ok"}`
4. `docker ps` → `mcp-query-1c` в списке
5. `sudo systemctl enable ai-stack.service` → enabled
6. `kimi mcp test mcp-query-1c` → Connected
7. Тестовый запрос `add_custom_query`:
   ```bash
   curl -s -X POST http://localhost:15372/mcp \
     -H "Content-Type: application/json" \
     -d '{
       "jsonrpc": "2.0",
       "id": 1,
       "method": "tools/call",
       "params": {
         "name": "add_custom_query",
         "arguments": {
           "name": "test_query",
           "sqlText": "ВЫБРАТЬ 1 КАК Поле1 ПОМЕСТИТЬ ВТ_Тест"
         }
       }
     }'
   ```
   Ответ должен содержать `status: created` и `nodesCount`.
