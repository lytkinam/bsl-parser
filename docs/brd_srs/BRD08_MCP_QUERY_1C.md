# BRD08 — MCP_QUERY_1C: Сервис-обёртка над 1C MCP-сервером

**Версия:** 1.0  
**Дата:** 2026-06-03  
**Статус:** Реализовано  
**Задача Redmine:** #646

---

## 1. Обзор

MCP_QUERY_1C — это отдельный MCP-сервис, который:
- Вызывает внешний MCP-сервер `1c-mcp-server-popov` (BRD06) для получения SQL-запросов по параметрам регламентированных отчётов 1С.
- Сохраняет полученные запросы локально и выполняет их полный разбор через конвейер SDQL (BRD06).
- Предоставляет MCP-интерфейс, где вместо `sqlText`/`baseName` используется имя параметра отчёта.
- При повторном вызове обновляет разбор (перезапрашивает запрос из 1С и перестраивает артефакты).

## 3. Бизнес-требования (REQ)

### REQ-08.01 Получение параметра из 1С
Сервис должен уметь вызывать метод `list_query_param` внешнего MCP-сервера `1c-mcp-server-popov`, передавая имя параметра, и получать текст SQL-запроса.

### REQ-08.02 Пагинация больших запросов
Если запрос превышает 100000 символов, сервис должен поддерживать пагинацию через аргумент `part_query` (0, 1, 2...). Пустой ответ означает конец запроса. Сервис должен автоматически склеивать части.

### REQ-08.03 Сохранение и кэширование
Полученный запрос должен сохраняться локально в файловой системе вместе с метаданными (имя параметра, источник, дата обновления).

### REQ-08.04 Полный разбор запроса
После получения запроса сервис должен выполнять полный 8-шаговый разбор через `SdqlPipeline`: SDBL_PARS, LINE_PARS, hierarchy, field_lineage, FULL_PARS, full_field_lineage, restored_queries, verification.

### REQ-08.05 Повторное обновление
При повторном вызове для существующего параметра сервис должен иметь возможность перезапросить запрос из 1С и перестроить все артефакты.

### REQ-08.06 Добавление произвольных запросов
Сервис должен позволять добавлять SQL-запросы напрямую (без обращения к 1С), например для тестирования или для запросов из других источников.

### REQ-08.07 Работа с сохранёнными данными
Все методы анализа (получение моделей, иерархии, field lineage и т.д.) должны работать с сохранёнными артефактами без необходимости повторного разбора.

### REQ-08.08 Список параметров
Сервис должен предоставлять метод для получения списка всех кэшированных параметров с возможностью фильтрации по имени.

## 4. Бизнес-объекты

### OBJ-08.001 QueryParameter (Параметр запроса)
| Атрибут | Тип | Описание |
|---------|-----|----------|
| name | String | Имя параметра из 1С (например, `258_произвЗапр_такс6.0`) |
| sanitizedName | String | Имя, безопасное для файловой системы |
| sqlText | String | Текст SQL-запроса |
| baseName | String | Имя для артефактов разбора |
| updatedAt | Instant | Дата последнего обновления |
| source | Enum {ONEC, CUSTOM} | Источник: из 1С или добавлен вручную |
| nodesCount | int | Количество узлов после разбора |

### OBJ-08.002 QueryParameterStore (Хранилище)
Файловая структура:
```
mcp_query_1c_storage/
├── parameters.json              # Реестр всех параметров (JSON-массив)
├── <sanitized_name>/            # Директория параметра
│   ├── query.sql                # Исходный SQL-запрос
│   ├── parameter.json           # Метаданные (OBJ-08.001)
│   └── artifacts/               # Артефакты разбора SDQL
│       ├── SDBL_PARS/
│       ├── LINE_PARS/
│       ├── FULL_PARS/
│       ├── field_lineage/
│       ├── full_field_lineage/
│       ├── RESTORED_QUERIES/
│       ├── EXTRACTED_QUERIES/
│       └── VERIFICATION/
```

## 5. Интеграции

### INT-08.001 1C MCP Server (test_popov)
- **URL:** `http://192.168.117.247/npf_ops_users_test_popov/hs/mcp`
- **Протокол:** JSON-RPC 2.0 over HTTP POST
- **Метод:** `list_query_param` с аргументами `name` и `part_query`
- **Ограничение:** Максимум 100000 символов в одном ответе

### INT-08.002 SDQL Pipeline (BRD06)
- **Интерфейс:** `SdqlPipeline.analyze(sqlText, outputDir, baseName, detailed)`
- **Результат:** 8 типов артефактов в директории `artifacts/`

---

## 6. Ограничения и допущения

- Сервис предоставляет только чтение метаданных 1С через MCP; прямой доступ к ИБ 1С отсутствует.
- Пагинация `part_query` поддерживается на стороне 1C; если 1C не поддерживает аргумент, сервис работает в обычном режиме.
- Хранилище файловое; для production может потребоваться миграция на БД.
- Имена параметров санитизируются для использования в именах директорий.
