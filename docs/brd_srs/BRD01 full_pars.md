# 1. Необходимо создать третий уровень парсинга full_pars (отдельный каталог), 
## 1.0. Основная идея, необходимо в структуре парсинга определить полевую зависимость между запросами, полевая зависимость строиться на уровне полей в select и условий в where, condition, group by и having.
### Алгоритм определения полевой зависимости тот же, что и в child_fields. Для просты дальнейшего использования для каждого поля добавляется свой id.
## 1.1. Источник данных: парсинг происходит исключительно по данным в каталоге line_pars, за основу берется  line_pars как первоначальная структура.
## 1.2. каждому полю в select присваивается свой field_ id (скозная нумерация).
## 1.3. Необходимо расширить структуру блока select, на child_fields для каждого поля в отдельности, алгоритм определения child_fields тоже, что и в field_lineage. берем только один уровень, дальше по иерархии не идем. 
## 1.4. В child_fields должен быть указан в том числе и field_id. если используеся таблица физических данных, то field_id в таком случае отсутствует.
## 1.5. Определение полей child_fields добавляется в блок where, condition, group by и having.

# 2. Необходимо создать отдельный каталог full_field_lineage, 
## 2.0. Основаня идея: необходимо собрать все "требования"/"данные" влияющие на результат запроса по конкретному полю.
### 2.0.0 Первоначально ведем разработку на примере одного поля {74, [ЗадолженностьПенсии]} для middle_example, полей может быть передано несколько
### 2.0.1 В файл должна попасть урезанная структура full_pars.
### 2.0.2 В full_pars остаются:
#### 2.0.2.1 В where, condition, group by и having выбранной ноды все существующие поля.
#### 2.0.2.2 В Select выбранной ноды: выбранные поля, плюс поля из group by.
#### 2.0.2.3 В соответствие со всеми имеющимися полями в where, condition, group by и having определяются используеммые ноды, по child_fields в них.
#### 2.0.2.4 Для каждой использованной ноды вызывается та же функция (тот же алгоритм) {child_fields[].id,[child_fields[alias]]}, где child_fields[alias] содержит все поля как из select, так и из where, condition, group by и having, полученные из соответствующей id. То есть здесь нужна группировка по id таблицы.

### 2.1.1. Структура подкаталогов аналагичная структуре field_lineage
### 2.1.2. для каждого поля создается свой файл. название файла аналогично, за исключением суффикса, вместо FLS_, суффикс FFL.
